# ADR-016. Crypto-shredding в WORM-аудите

- **Статус:** принято на уровне схемы; хранилище ключей — Vault Transit (этап 4).
- **Контекст.** Аудит неизменяем (hash chain, MinIO Object Lock), но право на удаление ПДн (§18.3, Закон РК
  «О персональных данных и их защите») требует необратимо удалять персональные данные.
- **Решение.** ПДн-поля записи аудита сериализуются отдельно и шифруются AES-256-GCM ключом tenant (в
  дальнейшем — ключом субъекта); `tenant_id` — associated data. Хэш записи считается **по шифртексту**, поэтому
  уничтожение ключа делает ПДн нечитаемыми, а цепочка остаётся верифицируемой. Реализация —
  `services/audit` (`KeyStore`, `ShredTenantPII`), тест — `TestCryptoShredding`.
- **Открытые вопросы.** Гранулярность ключей (tenant vs субъект) и их число; ротация без перешифрования
  WORM-копий (envelope encryption: DEK на период, KEK в Vault); процедура подтверждения удаления для субъекта.
