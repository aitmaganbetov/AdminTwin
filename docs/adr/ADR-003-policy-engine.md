# ADR-003. Движок политик

- **Статус:** временное решение (Этап 0); окончательный выбор OPA-Rego / Cedar — до завершения этапа 0.
- **Контекст.** ТЗ §11.2 п.3 требует единую точку решений (tenant, actor, asset, scope, risk, режим
  автономности, separation of duties, legal hold). Таблица технологий §3.5 называет OPA/Rego, ADR-003 оставляет
  Cedar альтернативой.
- **Решение.** Матрица §11.4 реализована встроенным Go-движком `services/policy.Builtin` за интерфейсом
  `policy.Engine`. Вызывающий код (Change Coordinator) зависит только от интерфейса. Правила покрыты
  табличными тестами (`services/policy/policy_test.go`), которые станут спецификацией для Rego/Cedar-реализации.
- **Последствия.** (+) Ядро работает без внешнего процесса OPA; тесты детерминированы. (−) Tenant не может
  писать собственные правила до появления OPA/Cedar-адаптера. Следующий шаг — `policy.OPA` с теми же тестами
  (тесты прогоняются против обеих реализаций), затем выбор по критериям: выразительность ABAC, производительность
  (< 5 с proposal → decision, §17.1), инструменты аудита правил.
